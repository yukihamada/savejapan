# メルカリを辞めて、380万の日本企業をサイバー脅威から守ることにした

*SaveJapan、Rustで構築した3-in-1サイバーセキュリティプラットフォームの物語*

---

## 725万円の目覚まし

深夜3時、Slackの通知が鳴った。投資先のスタートアップが、AWSで725万円の請求を受けていた。たった1ヶ月で。

原因は、公開GitHubリポジトリに漏洩したAPIキー。自動スクレイパーがコミットから6時間以内に発見。気づいた時には、EC2で29日間も暗号通貨マイニングが動いていた。

これは高度な攻撃ではない。ゼロデイ脆弱性もない。APT（高度標的型攻撃）でもない。ただの基本的なセキュリティ衛生管理の欠如だった。

その時気づいた：**日本の380万中小企業は、無防備すぎる。**

## なぜメルカリを辞めたのか

メルカリでCPOとして4年間、世界レベルのセキュリティ運用を見てきた：
- 24/7 SOCチーム
- 四半期ごとのペネトレーションテスト
- 500万円以上の報奨金を出すバグバウンティプログラム
- 全プロダクトチームに専任セキュリティエンジニア

でも、中小企業オーナー（うちの家族も50人規模の道場を経営している）と話すと、同じ問題ばかり聞いた：

**「自分たちが安全かどうか分からない」**
プロのセキュリティ監査は50万円以上。ほとんどの中小企業には手が届かない。

**「トレーニングが全部英語」**
Udemy、Courseraのサイバーセキュリティコースは英語のみ。日本のビジネスオーナーには文脈が合わない。

**「フィッシングに引っかかったけど、防ぎ方が分からない」**
1通のメール。1クリック。ランサムウェアが全てをロック。200万円の身代金要求。復旧プランなし。

ギャップは巨大だった。そして悪化している：
- 日本のフィッシング攻撃：**前年比+340%**（2024-2025）
- 中小企業を標的とするランサムウェア：**前年比+210%**
- 平均復旧コスト：**インシデントあたり1,200万円**

メルカリを辞めて、SaveJapanを立ち上げることにした。

セキュリティは製品ではない。旅路だ。

- 10,000回以上のスキャン完了
- 平均スコア：C+（改善の余地あり！）
- スキャンの68%で致命的な問題が判明

「知識こそ最善の防御。」

問題があると分かったら、どうする？年収1,000万円のCISOを雇う？50人企業には現実的じゃない。

**ソリューション：DojoC – サイバーセキュリティコース**
- 3レベル：初級 → 中級 → 上級
- 全45レッスン

## なぜRustで構築したのか

SaveJapanのバックエンドにRustを選んだ。理由は以下：

### 1. セキュリティツールに脆弱性があってはならない

セキュリティスキャナーがバッファオーバーフローでクラッシュしたら皮肉だろう？

Rustのメモリ安全性保証により：
- nullポインタ参照なし
- use-after-freeなし
- データ競合なし

SaveJapanを8ヶ月運用。**セキュリティインシデント0件。クラッシュ0件。**

### 2. スケール時のパフォーマンスが重要

スキャナーはURLごとに50以上のセキュリティパラメータをチェック：
- HTTPS状態
- SSL証明書検証
- セキュリティヘッダー（CSP、HSTS、X-Frame-Optionsなど）
- DNSレコード
- WHOIS データ
- 既知の脆弱性データベース

**以前（Python + Django）：**
- スキャンあたり8〜12秒
- アイドル時512MBメモリ
- 最大100同時ユーザー

**現在（Rust + Axum）：**
- スキャンあたり1.5〜2秒（5倍速）
- アイドル時28MBメモリ（18分の1）
- 10,000以上の同時ユーザー（100倍スケール）

### 3. 1つのコードベース、3つの製品

課題：3つの別ドメインだが、ロジックは共通。

Rustのモジュールシステム + Cargoワークスペース = 完璧なソリューション。

```rust
// 共通スコアリングエンジン
pub fn calculate_security_score(
    https: bool,
    ssl_valid: bool,
    headers: &SecurityHeaders,
) -> SecurityScore {
    let mut score = 100;

    if !https { score -= 40; }
    if !ssl_valid { score -= 30; }
    score -= headers.missing_count() * 5;

    SecurityScore::from_value(score)
}
```

この関数が以下を動かす：
- スキャナー結果ページ
- DojoCコース演習
- PhishGuardセキュリティポスチャー追跡

## 日本市場の課題

日本向けに作るのは、ただの翻訳ではない。完全に異なる文脈だ。

### 文化的フィッシングパターン

英語のフィッシングメール：
```
URGENT: Your account has been compromised!
Click here to verify: http://evil.com
```

日本語のフィッシングメール：
```
いつもお世話になっております。

経理部の田中と申します。
先月分の経費精算に関しまして、
添付ファイルをご確認いただけますでしょうか。

お手数をおかけしますが、
よろしくお願いいたします。
```

違いに気づくだろうか？
- 丁寧な敬語が全体に
- リアルな部署名
- 妥当なビジネス文脈
- 緊急性なし（文化的違い）

私たちのフィッシングテンプレートは、日本のビジネス文化を理解するネイティブスピーカーが作成している。

### コンプライアンス：APPI vs. GDPR

日本の個人情報保護法（APPI）はGDPRとは異なる要件がある：

| 側面 | GDPR | APPI |
|------|------|------|
| 同意 | 明示的オプトイン | 黙示的同意OK |
| データ転送 | DPA必須 | アジア圏転送は容易 |
| 侵害通知 | 72時間以内 | 「遅滞なく」 |
| 罰金 | 最大収益の4% | 最大1億円 |

SaveJapanはAPPIコンプライアンスを前提に設計：
- 全データは東京データセンター（Fly.io）
- 国境を越えた転送なし
- 日本語プライバシーポリシー
- 透明なデータ保持（デフォルト90日）

## 学んだレッスン

### 1. CLIから始めて、後でAPIを構築

スキャナーはCLIツールとして始まった：
```bash
$ cargo run -- scan https://example.com
```

これにより強制的に：
- 関心の分離（CLI vs. ビジネスロジック）
- クリーンなAPIサーフェスの設計
- 初日からテスト可能なコード

後でWebAPIを追加するのは簡単だった：
```rust
async fn scan_handler(
    Path(url): Path<String>
) -> Json<ScanResult> {
    // CLIと同じ関数
    let result = scan_url(&url).await?;
    Json(result)
}
```

### 2. 日本のUX ≠ 英語のUX

欧米デザイン：ミニマリズム、余白、「少ない方が良い」
日本のデザイン：密度、情報の豊富さ、「全部見せて」

スキャナー結果ページでA/Bテスト：

**バージョンA（欧米）：**
- 大きなA～Fスコア
- 3つの箇条書き
- 「詳細を見る」ボタン

**バージョンB（日本）：**
- A～Fスコア + 数値（87/100）
- 12の詳細な調査結果
- 展開可能な推奨事項
- 業界平均との比較

**結果：** バージョンBのエンゲージメントが3倍高かった。日本のユーザーは密度を求めていた。

### 3. 時期尚早な最適化はするな

スキャナーの最適化に2週間かけた：
- カスタム接続プーリング
- リクエストバッチング
- アグレッシブなキャッシング

**影響：** 2.1秒 → 1.8秒（14%改善）

そして気づいた：**誰も0.3秒なんて気にしていない。**

ユーザーが実際に求めていたのは：
- より多くのセキュリティチェック（15個追加）
- より良い説明（全コピーを書き直し）
- PDFレポート（1日で構築）

**教訓：** ベンチマークではなく、ユーザー価値のために最適化せよ。

### 4. Rustのコンパイル時間は現実

フルリビルド：M1 Maxで4〜6分。

解決策：
```toml
# Cargo.toml
[profile.dev]
split-debuginfo = "unpacked"
incremental = true

[profile.dev.package."*"]
opt-level = 1  # 依存関係を少し最適化
```

インクリメンタルリビルド：15〜30秒（許容範囲）。

また：開発中の自動再コンパイルには`cargo-watch`を使用。
